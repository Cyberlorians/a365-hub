# A365 Hub: Project Outline

**Adopt AI. Govern Agents. Protect the Business.**

The workshop is the vehicle; secure AI adoption is the offer. This is the current
eight-module security journey, replacing the older six-module/multiple-build outline.
The [master plan](06-customer-learning-plan.md) is the detailed curriculum authority.

## Audience and outcomes

Identity, security, SOC, data/compliance, platform, and AI adoption teams learn to:

- Establish an approved useful agent task and actual actor/authority boundary.
- Explain the playbook's identity-based and AI-native attack surfaces.
- Review creation, technical control, sponsorship, permissions, and lifecycle.
- Test supported data controls and record owned improvement evidence.
- Attribute activity, investigate with the right evidence, scope response, and verify.
- Turn findings into an accountable 30-day pilot and licensing/readiness decision.

## Grounding and architecture

Every module uses Cloud-Architekt's Agent Identities chapter as the security spine:
**risk -> control -> evidence -> decision**. Microsoft Learn is the product-behavior
authority. Stefano provides a candidate runtime; approved GBB material informs selected
separate workload fixtures/hunts; Blue16 inspires original explanations.

Do not assume the GBB workload fixture and toolkit agent are one target. Verify actual
identifiers, source coverage, authentication route, schemas, and join keys.
Use current `AgentsInfo` inventory guidance and applicable activity/behavior/alert
tables only after tenant validation, not an assumed `AIAgents` query.

## Delivery boundary

The current publication is for content review. No tenant fixtures, test accounts,
automation, simulations, or security policies were deployed for these drafts.
After content review, approve the environment and
[per-module data/automation plan](06-customer-learning-plan.md#16-per-module-data-and-automation-preparation).
Then prove the runtime, test fresh learners, rehearse independently, and release the
appropriate mode. No live takeover, automated containment, or production changes are
mandatory learning activities.
