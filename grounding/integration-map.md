## GBB access and reuse

The reviewed GBB extraction is not committed or redistributed. Upstream access can
require authorization, so external delivery needs approved material/links and rights.
Do not import internal enrollment steps, instructions to publish credentials, full SDK
or AWS setup, or every simulator into the core first release.

Use selected SDK/registration explanation where compatible; selected logging/hunting
patterns; and one approved separate AI-workload case. Request success does not prove
an alert; diagnostic discovery does not prove activity collection; mocks/IAM checks do
not prove live platform connections.

## Stefano runtime boundaries

The ACA-OBO label does not prove the web route uses OAuth OBO. The reviewed UI documents
`MAIL_TOKEN_MODE=direct` and delegated-user Mail access. It sends from the signed-in
user's mailbox. The setup includes a blueprint secret and broad instructor consents:
review them before running or claiming secretless/least-privilege operation.

No full Demo Builder or multi-agent deployment is a first-release prerequisite.
Rights must be confirmed before redistributing adapted toolkit code.

## Separate targets and honest evidence

The toolkit agent and GBB model/workload target are initially separate. Record actual
typed IDs, time, source, engine, expected/observed result, and provenance. Do not join
streams by display name or fabricate an end-to-end attack.

Label records current run, verified prior run, synthetic example, or missing. Synthetic
fixtures are teaching inputs, not fabricated security-table rows or proof of enforcement.
Generate/deploy only after review, scoped approval, cost bounds, and a reset manifest.
