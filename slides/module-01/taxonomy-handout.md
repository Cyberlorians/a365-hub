# Module 1 Learner Reference

**A correctly authenticated agent can still be manipulated into misusing legitimate access.**

Four questions: **What agent/purpose? Who is accountable and acts? Which data/tools/
permissions? What happened, which evidence, and which decision?**

| Evidence lens | Can help establish | Cannot prove alone |
|---|---|---|
| Identity/access | Authentication, grants, management changes | Safe runtime behavior |
| Runtime/tool | Instruction, tool/action, result where instrumented | Complete policy coverage |
| Workload/data | Access/send outcome and supported control result | Universal prompt protection |
| Applicable network | Traffic on supported forwarded/inspected routes | Local MCP traffic or injection blocking by mere capture |

Five Entra pillars: identity/lifecycle; creators/managers; permission governance;
flow-appropriate CA/risk; supported network protection. Add Purview data controls,
owned Compliance Manager action, and Defender/ISOC investigation/response.

| Module | Main output |
|---|---|
| 1. Frame risk and controls | Readiness worksheet |
| 2. Establish normal behavior | Actor/tool/data/evidence passport |
| 3. Map identity and authority | Actual diagram and blast radius |
| 4. Govern lifecycle/access | Accountable decision |
| 5. Protect data | DLP evidence and improvement action |
| 6. Recognize misuse | Attributed scenario record |
| 7. Investigate/respond | Timeline, scoped response, retest |
| 8. Prove readiness/adopt | Four findings and a pilot decision |

Audit is not blocking. Generated content does not automatically inherit source labels.
Prompt review is not an implemented approval boundary. Missing evidence is a gap,
not proof of safety. See the [master plan](../../docs/06-customer-learning-plan.md).
