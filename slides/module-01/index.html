Part 2 / Why agents need security

See It.
Control It.
Protect It.

An AI agent is a digital coworker. It reads, makes decisions, and acts with real access.

See it

Know the agent's purpose, owner and operating context.

Control it

Approve its access, data and tool boundaries.

Protect it

Check what happened and act on the evidence.

Companies want agents for the work they do. Our job is to see them, control them and protect them.

Takeaway: know what to ask before trusting an agent. No worksheet or written submission.

A simple example / Not a setup exercise

A question can lead to an action.

Imagine an employee asks: “How do I get help with my laptop?” An IT support agent could find approved guidance, answer, or use a configured tool to raise a ticket.

Read

Find information the employee is allowed to use.

Decide

Choose an answer or the next approved step.

Act

Use a tool only when the task and permissions allow it.

A helpful answer and an authorized action are different things. A valid sign-in does not prove either is safe.

This is an illustration, not a claim that our registry record has these capabilities. Module 2 uses an actual agent and checks its result.

The big picture / Four learning pillars

Working. Accountable. Safe. Useful.

Management

Is the agent working as expected?

Governance

Who owns it, and what can it access?

Security

How would we notice unsafe activity, and who would investigate?

Business value

Is it delivering useful results for its cost?

These are four questions, not four extra labs. No single dashboard answers all of them.

Management / Understand what happened

Check the result. Watch the service. Follow the steps.

Evaluation

Did it perform the task well?

Compare an answer or action with an expected result.

Monitoring

Is it working reliably over time?

Look for changes in errors, response time and usage.

Tracing

What steps did it take?

Follow recorded model calls, tools and service activity.

A registry entry tells you an agent is listed. It does not prove the agent worked or behaved safely.

Concepts grounded in Microsoft Foundry observability. Availability depends on the actual runtime and integrations. No Foundry setup in this module.

Lab 3 / Read-only registry walkthrough

Open a record. Ask better questions.

What do Data & tools and Permissions report?

Relay is a staged registry/risk example, not the illustrated IT helpdesk runtime. Viewing its record does not run it.

Governance / Someone must own the next action

A listed agent still needs an accountable owner.

Business purpose

Who approves the work this agent should do?

Technical management

Who maintains its configuration and access?

Lifecycle

Who reviews it and retires it when the job ends?

Created by is not automatically the current owner. A blank owner field means follow up, not guess.

Finish the walkthrough and discuss one ownership gap. Module 3 covers identity; Module 4 covers governance.

Purview / Data security and compliance follow-through

Protect the data. Record the evidence.

Know your data

Find sensitive information and see who can reach it.

Limit unsafe sharing

Data loss prevention (DLP) can warn or block. Test it on the real workload.

Prove the fix

Compliance Manager tracks each improvement: an owner, an action and a status.

Audit records what happened. It does not block anything.

Module 5 tests one control. A compliance score is not a certification.

Evidence map / Reference for instructor and later modules

Where would you check the evidence?

QuestionWhere to look
Who signed in or changed access?Entra > Entra ID > Monitoring & health > Sign-in logs or Audit logs
Which model or tool steps ran?Ask the runtime owner for recorded traces. Integrated Foundry apps can use Azure Monitor Application Insights.
What workload activity was audited?Purview > Solutions > Audit > Search. Requires supported events, audit access and retention.
Was a threat investigated?Defender > Incidents & alerts > Incidents or Alerts. No alert does not prove no activity.

This is a map for later modules, not another portal exercise. AI Reader does not grant access to these other evidence sources. No alert does not mean no risk.

Business value / Start with the outcome

More activity is not automatically more value.

Useful outcome

Did employees get correct help or complete an approved task?

Quality and effort

Was time saved without more mistakes or rework?

Cost

What do usage, licensing and operations cost?

Agree on the outcome first. Then measure whether the agent improves it.

Usage and token counts are clues, not a complete cost or value calculation. The adoption decision follows in Module 8.
