Part 2 / Why agents need security

See It.
Control It.
Protect It.

An AI agent is a digital coworker. It reads, makes decisions, and acts with real access.

See it

Know the agent's purpose, owner and operating context.

Control it

Approve its access, data and tool boundaries.

Protect it

Check what happened and act on the evidence.

Companies want agents for the work they do. Our job is to see them, control them and protect them.

Takeaway: explain a sample agent's task, knowledge, actions and evidence. No worksheet or written submission.

Microsoft Agent Academy / IT helpdesk scenario

Help an employee. Show the source.

An employee needs help with a device or an IT policy. The helpdesk agent should use approved support guidance, explain the answer and escalate when it cannot verify a solution.

Useful task

Answer a support question from the prepared Contoso IT knowledge. Do not invent a policy or ask for passwords.

Knowledge

The Academy setup supplies an IT SharePoint site with sample policy pages and Devices and Tickets lists. A list is not automatically an agent tool.

Boundary

Answer and explain today. Creating a ticket or changing a device requires a separately configured tool, permission and test.

Four review questions: What exists? Who owns it and who acts? What can it reach? What evidence shows what happened?

Based on Agent Academy Recruit, Mission 06. Our security review is an extension, not a claim that Microsoft supplies a ready-deployed tenant.

Read the sample / Distinguish its components

Knowledge answers. Tools act.

Purpose

The employee problem this agent is meant to solve.

Instructions

Guidance for answering, asking questions and escalating. Instructions are not an access-control policy.

Knowledge

Approved IT pages and support sources used to ground an answer. Verify access and the cited content.

Tools

Configured actions such as a device lookup or ticket creation. Inspect the connection and permissions separately.

A good answer does not prove a tool ran. A configured tool does not prove it is authorized safely.

The helpdesk example / Identity and behavior

A valid sign-in does not prove safe advice.

Misused access

Someone changes a connection or grants the agent access to IT information outside its approved scope.

Check: identity, grants and directory changes in Entra; source permissions and connection settings.

Misleading content

An untrusted page tells the agent to ignore its support task. The agent may give unsafe advice while correctly signed in.

Check: the question, retrieved source, answer and any actual tool action in the test activity.

Compare who had access with what the agent actually did. Do not execute an attack or enter credentials into the chat.

Purview / Data security and compliance follow-through

Protect the data. Record the evidence.

Know your data

Find sensitive information and see who can reach it.

Limit unsafe sharing

Data loss prevention (DLP) can warn or block. Test it on the real workload.

Prove the fix

Compliance Manager tracks each improvement: an owner, an action and a status.

Audit records what happened. It does not block anything.

Module 5 tests one control. A compliance score is not a certification.
