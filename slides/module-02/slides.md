## Slide 5 - Review, request send, verify receipt

**Planned time:** 5 minutes (core).

Proposed activity / Only after approved lab setup

### Review. Request send. Verify receipt.

- Check the message against the brief.

- Confirm the real approved internal test recipient.

- Explicitly request sending the reviewed message.

- Verify actual receipt, sender, subject, and time.

A draft, a healthy container, or a successful HTTP response is not proof of mail delivery.

If the result is uncertain, check for receipt before retrying. Do not duplicate sends or widen permissions to recover.

## Slide 6 - Find evidence without inventing it

**Planned time:** 7 minutes (core).

Proposed activity / Evidence provenance

### Find evidence without inventing it.

| Check | Expected proof after preparation | Not equivalent |
| --- | --- | --- |
| Task | Actual internal receipt and intended sender | Draft text or tool success message alone |
| Actor / tool | Real user, tool/action, target/resource, time, result | A matching display name |
| Management / telemetry | Verified registration and actual downstream evidence path | Exporter configured or empty inventory |
| Control | Observed supported policy/result, if tested | Successful delivery proves security |

**Label every record:** current run / verified prior run / synthetic example / missing.

## Slide 7 - Complete the agent passport

**Planned time:** 5 minutes (core).

Learner output / Do not fill gaps with guesses

### Complete the agent passport.

### Identity and authority

- Purpose and platform/version

- Technical owner and sponsor

- Acting user and identifier types

- Actual access route and grants

### Actions and evidence

- Tool, resource, allowed data/recipient

- Action, result, and timestamp

- Evidence location, target, and mode

- Open gap and response owner

Expected boundary: the reviewed synthetic status message to one approved internal recipient. An unexpected recipient or tool needs investigation.
